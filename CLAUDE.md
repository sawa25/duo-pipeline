# CLAUDE.md — duo-pipeline (единый источник истины инструмента)

Оркестратор «исполнитель ↔ ревью» (режимы solo / pair / duo) для **любых** git-проектов
на машине. Код живёт ТОЛЬКО здесь (далее `$DUO_HOME` — каталог клона этого репозитория);
проекты хранят у себя лишь свои данные: `pipeline/<task>/` (артефакты серий) и
`.duo/config.json` (тонкие переопределения). Руководство: `docs/CHEATSHEET-CONTROL.md`.

## Правила работы в этом репозитории

1. **Python**: ≥ 3.11, **только stdlib** (оркестратор — один скрипт без зависимостей).
   Для разработки нужны `ruff` и `pytest` в том интерпретаторе, которым вы гоните гейты
   (`make check` берёт `python3` из PATH; иной — `make check PY=/путь/к/python`).
2. **Гейты**: `make check` = `ruff check .` + `pytest tests`.
   Свой `-q` к pytest НЕ добавлять (в `pyproject.toml` он уже есть; второй даёт `-qq`
   и итоговая строка `N passed` не печатается). Перед сдачей — оба зелёные.
   Это КОНТУР 3 («CI инструмента»): GitHub Actions в репозитории нет, `make check` — единственный
   гейт, а потребитель красного — все проекты, подключённые к инструменту (их CI тесты
   оркестратора не исполняет). Контуры CI проекта и гейтов серии (`duo gates`) — другие;
   различия и правила — `docs/CHEATSHEET-CONTROL.md`, раздел «CI и гейты».
3. **Полные абсолютные пути** в командах.
4. **Границы записи**: править файлы только внутри `$DUO_HOME`. Проекты-потребители можно
   читать для справки (их `.duo/config.json`), но НЕ менять. Не трогать: `~/.claude*`,
   `~/.cursor`, `~/.config`, `~/.local`, systemd-юниты, каталоги данных других проектов.
   Не запускать `systemctl`, `notify-send`, `selftest` и любые команды, которые зовут модель
   (`claude`) или ходят в сеть. Тесты не должны этого делать тоже (подмена транспорта — как в
   существующих `tests/unit/test_duo_*.py`).
5. **Тесты изолированы от машины**: реестр проектов и состояние надзора в тестах —
   только во временных каталогах (`XDG_CONFIG_HOME`, `XDG_STATE_HOME` → `tmp_path`);
   живой `~/.local/state/duo-supervisor/state.json` и `~/.config/duo-pipeline/` не
   читать и не писать.
6. **Не коммитить и не мержить** — версионированием управляет оркестратор/человек.
   Не трогать `pipeline/<task>/state.json`, `.lock`, `orchestrator*.log`, `transcripts/`.
7. **Совместимость**: формат `state.json` и флаг `--config` со старым конфигом, где
   есть ключ `repo`, не ломать — по инструменту работают уже запущенные серии.
8. **Репозиторий публичный — без следов конкретных проектов и машин**: никаких имён
   проектов-потребителей, домашних путей, хостов; проектная специфика — только в
   `.duo/config.json` ПРОЕКТА. Это проверяет `tests/unit/test_duo_public_hygiene.py`.
   Пути интерпретатора (`gates.python`) в проектный конфиг не писать: они непереносимы
   между машинами (подробнее — `docs/PROJECT-SETUP.md`, «Несколько машин»).
9. Отвечать по-русски; код и идентификаторы — как в существующем стиле файла.
